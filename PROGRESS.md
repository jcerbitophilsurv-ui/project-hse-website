## Phase 6 — Real pricing data: quote calculator rebuilt on lookup tables (2026-09-06)

**Status**: Built and verified locally. This is the "corrected arithmetic" the Build Sheet's G7 task was waiting on — client provided `Pricing/Solar-Pricing-Reference-by-Consumption.xlsx`, transcribed into `content/pricing-tables.yml`.

**What changed**: the calculator no longer computes system size from a formula (yield × reduction % → panels → inverter). It now looks up a pre-priced system directly from `content/pricing-tables.yml`'s 31 consumption tiers (300-2,000 kWh), for whichever of 3 real products applies:
- **Ongrid w/ Net Metering** (net metering = "Yes") — sized to ~100% of usage, exports credited at ₱7.00/kWh.
- **Hybrid** (net metering "No"/"Not sure" + wants battery backup = "Yes") — battery + panels sized to ~100% coverage.
- **Ongrid, no export** (net metering "No"/"Not sure" + no battery) — sized to daytime load only, ~40% coverage, cheapest option.

Since each product now has a **fixed** coverage percentage (not a customer-adjustable slider), the old "3 scenario cards at 50/70/100%" UI is gone — the calculator now shows **one recommended system** based on the customer's actual answers (confirmed with the user before building — see prior turn). **Second correction (2026-10-07): the real root cause was CSS, not JS — the above fix didn't actually fix anything.** User reported the battery row *still* staying visible after selecting "Yes" (confirmed on `horizonsolar.net` directly via a live fetch of the deployed `quote-calculator.js`, and in an incognito window to rule out caching — the deployed code was already correct, and it still didn't work). The actual bug: `#batteryRow` carries `class="form-row"`, and `.form-row { display: flex; ... }` is an author-stylesheet rule with equal specificity to (and listed after) the browser's default `[hidden] { display: none }` UA rule — so it silently wins the cascade and `hidden` has never had any visual effect on this element, in either direction, regardless of what `batteryRow.hidden` gets set to in JS. **This project has hit this exact bug shape before** (see Phase 3: `.quote-loading[hidden]`) and has the fix pattern already established for every other flex/block container that gets toggled via `hidden` (`.quote-loading[hidden]`, `.quote-form-fields[hidden]`, `.quote-send-error[hidden]`, `.modal-overlay[hidden]`) — `.form-row` was simply the one container that never got its own `[hidden]` override added, since until now nothing had ever actually needed `.form-row` to be dynamically hidden. Fixed with one CSS rule: `.form-row[hidden] { display: none; }` right next to the base `.form-row` rule. This is a general fix (applies to any `.form-row`, not just `#batteryRow`), which also forecloses the same latent bug for any future `.form-row` that gets a `hidden` attribute.

**Third adjustment (2026-10-07): changed the intended default UX, not another bug fix.** User directly edited `quote.html` (outside this session) to remove the `is-active` class from all three net-metering toggle buttons — no option is visually pre-selected anymore, where "No" used to be. Removed that sync-on-load line from `quote-calculator.js` entirely — `batteryRow` now simply stays in its default HTML `hidden` state (correctly hidden, thanks to the CSS fix above) until a net-metering button is actually clicked, at which point the existing click handler shows/hides it as before (hidden for "Yes", shown for "No"/"Not sure yet").
